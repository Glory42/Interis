Themes for the new design

Rose Pine, NULL://LOG and Marquee keep their names and personalities, and Tokyo Night is replaced by Nitrate. In every theme, each colour now has one job. Every theme defines the same roles, which are checked for contrast below. The specimen on each card is the same markup; only the colour values change.

What's wrong with the themes today

  • Two sources that disagree. Every theme is defined in both public/theme-registry.js and index.css. The registry's values are written inline at startup (index.html:73, theme-runtime.ts:42), so they override the CSS. The two have already drifted apart: Rose Pine's border is #655c8e in one and #3f3958 in the other.
  • Colours doing two jobs. Film uses the same colour as buttons and rockets in null-log (#00ff88), Tokyo Night (#7aa2f7) and Marquee (#b8123a), so "this is a film" and "press this" look the same. Rose Pine's film colour #e0a8a3 and accent #f4c2bf are nearly identical.
  • Missing roles. There's no like, warning or success colour, so the code hardcodes rose-500, amber-*, green-500 and #ef4444, which ignore the theme.
  • Contrast. Tokyo Night's secondary text #565f89 is about 2.8:1 against its background, below the 4.5:1 needed for small text (Tokyo Night is replaced below). Text selection is hardcoded black text (::selection{color:#000}), which breaks Marquee.
  • Leftovers from the old look. Each theme has glow shadows, background gradients and patterns, vignettes and its own corner radius. The new design removes all of these.
  • "Rose Pine" isn't quite Rose Pine. The default is loosely based on it (#171420 instead of the real base #191724). Either use the real palette, which the name promises, or rename it. I've used the real palette below.

The roles every theme defines

How it gets built

  • One source of truth. All theme colours live only in index.css under :root[data-theme-id]. The startup script in index.html only sets data-theme-id (and color-scheme for Marquee) before the app loads, so there's still no flash of the wrong theme. The registry keeps just the id, label, description and preview swatches for the settings picker.
  • Remove: per-theme --radius, button glow shadows, --theme-shell-gradient/pattern/vignette, and the modal gradient and pattern tokens.
  • Keep one flourish per theme, drawn only by shared components: null-log scanlines on backdrops and a phosphor glow on the primary colour; Nitrate sprocket-edged slates and heavy grain; Marquee serif titles and lighter grain. Rose Pine stays plain.
  • Selection becomes background: var(--primary); color: var(--primary-foreground).
  • Adding a theme (the add-theme skill and ADDING-THEMES.md) becomes "fill in these roles in one place". A contrast check over all four themes can run in the frontend tests, so a new theme can't ship unreadable text.
  • Tokyo Night → Nitrate migration. Add nitrate to the backend theme whitelist (users/constants/theme.constants.ts), run one data migration that moves users from tokyo-night to nitrate, then remove tokyo-night. Until that migration runs, the startup script should treat an unknown saved id as the default theme rather than leaving the page unstyled. The other three ids stay the same.
